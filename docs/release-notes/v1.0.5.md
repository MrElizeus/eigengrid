# EigenGrid 1.0.5

Authenticated HTTP clients can now apply AMBER material and publish prepared MD
stages through the same governed application operations as the local CLI. This
closes an interface gap that prevented an HTTP-owned mission from reaching the
existing material and execution workflow.

Force-field publication accepts equivalent ordering of source references while
preserving the exact original approved parameter digest. If publication has a
confirmed receipt but its projection was interrupted, the original HTTP operation's
explicit reconciliation route can finish that projection after verifying the current
identity, policy, approval and immutable inputs. It never admits a new effect, and
incomplete or ambiguous evidence remains fenced.

The new project/mission routes require the current authenticated identity, project
access, CSRF and exact-origin checks, typed request bodies, expected revisions and
distinct idempotency operations. Replayed and uncertain effects retain their existing
fences. The additive HTTP schema v2 preserves the published v1 migration and checks
both checksums; administrators must explicitly apply the HTTP schema update.

Protected mission-client configuration can select the canonical MD site-authority
path. User request bodies cannot override it. AMBER byte inspection retries only
bounded transient EAGAIN/EWOULDBLOCK failures while opening an artifact, retaining
nonblocking/no-follow flags and all identity, file-type and digest checks. It never
resubmits an engine because an artifact could not be read.

The agent's bounded file reader also retries transient EAGAIN/EWOULDBLOCK reads
without weakening file-type, size or no-follow checks. A new encrypted-backup stream
receiver limits incoming bytes, checks the disk reserve before and during transfer,
and serializes receivers without overwriting historical snapshots. The sender must
still decrypt and verify the stored copy.

These changes do not certify scientific protocols or widen production admission.
Numerical convergence, scientific acceptance and exact execution approvals remain
separate from successful submission, parsing and software verification.
