# EigenGrid 1.0.6

Persistent mission agents can now inspect capabilities, reviews, evidence and prepared
inputs; import prepared candidates; apply prepared material operations; publish MD
stages; and cancel missions. Scientific requests must already exist as immutable,
verified mission artifacts. Mutations retain exact agent-call approvals and canonical
scientific authority. The model cannot grant scientific approval or invoke a shell.

CLI and TUI sessions share a private HTTPS client for users without PostgreSQL access.
The client verifies the configured CA, actor and mission scope, retains pending requests
before transmission and explicitly recovers the original HTTP operation after a lost
response. Credential or certificate rotation preserves uncertain-operation fences.
Invalid private configuration does not silently fall back to a different authority.

System-build preflight now checks output identities, the complete immutable source set,
frozen draft and source-manifest contents, force-field publication, current approvals
and artifact collisions before admitting an effect. Existing inconsistent receipts
remain fenced and are not rewritten into successful publications.

AMBER minimization mapping v4 binds the numerical split to the exact approved protocol
and stage revision. Controls are still derived from the canonical stage; this avoids
requiring a biomolecular decision that does not describe a numerical algorithm. Legacy
v3 mappings retain their schema and digest semantics. Every process that parses or
renders v4 must run a compatible release.

These changes expand software functionality. They do not certify the protocol catalog,
extend an engine compatibility declaration or enable production dispatch without the
installation's exact qualification evidence and scientific approvals.
