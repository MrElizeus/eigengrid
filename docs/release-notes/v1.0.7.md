# EigenGrid 1.0.7

Creating a mission now commits its mission record, budget, project association and
objective evidence in one transaction. An evidence identifier collision or a failure
later in the batch leaves no partial mission. The legacy local creation service uses
the same atomic evidence insertion. Replaying a historical creation with missing
objective evidence does not silently fill the missing records.

Recovery of a lost HTTP creation response requires the original immutable mission
fields, matching budget and exact mission-owned objective evidence. A partial creation
remains pending instead of being reported as successful. Subsequent legitimate budget
consumption is preserved; recovery does not change accounting or re-execute creation.
Evidence identifiers remain globally unique; callers must use distinct identifiers
for distinct evidence records, including across users and missions.

This patch does not rewrite existing incomplete records, database migration history
or scientific approvals. Software and installation checks remain separate from the
scientific acceptance of individual protocols.
